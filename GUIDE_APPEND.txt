WHAT CHANGED & WHY
------------------
Ryan generated a private API key at nhentai.net/user/settings#apikeys
(format `nhk_…`, verified live 2026-09-04: HTTP 200 on /api/v2/search and
/api/v2/galleries/5 with `Authorization: Key <key>`).

Per nhentai.net/api/v2/openapi.json, the keyed tier (auth=user|key) is:
    /api/v2/search                10/min anon -> 20/min keyed
    /api/v2/galleries/{id}        20/min anon -> 45/min keyed
    /api/v2/galleries (list)      15/min anon -> 30/min keyed
    /api/v2/galleries/popular      8/min (flat — no keyed tier in spec)
    .../suggestions               60/min (flat — no keyed tier in spec)

Two gaps existed before this version:
  1. FOUR direct callers sent NO Authorization header even when the key
     was set (only hf_scraper.py and hf_scraper_lite.py did).
  2. Every shared token bucket was sized to the ANON tier, so the keyed
     headroom could never be used.

Phase 1 — every nhentai caller now sends `Authorization: Key <key>` when
NHENTAI_API_KEY is set in the environment (headers byte-identical to
before when it is unset — zero behavior change without the env var):
  * miniapp/backend/app/services/prefetch_cron.py        (_nh_headers helper)
  * miniapp/backend/app/services/scraper_bridge.py       (_nh_headers helper,
                                                          user-facing search
                                                          + detail fallback)
  * miniapp/backend/app/services/details_prefetch_cron.py (trending-tags fetch)
  * Bot2Fetcher/app/fetcher.py                           (_nh_headers helper,
                                                          _fetch_meta_direct)
  * ScraperBot/app/services/trending_tags.py             (settings-driven)
  (hf_scraper.py / hf_scraper_lite.py already had it — verified, untouched
  logic, comment refresh only.)

Phase 2 — buckets re-sized to the keyed tier:
  * Bot 0  miniapp/backend/app/services/nhentai_cache.py BUCKETS:
      search 10->20, galleries 20->45, galleries_list 15->30
      (popular 8 / suggestions 60 unchanged — flat tier)
  * Bot 1  ScraperBot/app/config.py defaults:
      BUCKET_SEARCH 10->20, BUCKET_GALLERIES 20->45,
      BUCKET_SEARCH_SCRAPER 8->16 (80% of 20 — BOT 0 keeps a 4-token reserve),
      NEW BUCKET_GALLERIES_SCRAPER=36 (80% of 45 — 9-token reserve),
      galleries_list fallback 15->30 in ScraperBot/app/cache.py
  * db.py docstring updated (anon -> keyed tier).
  ALL values stay env-overridable; the 80/20 split preserves the v1.14
  invariant that BOT 0's user-facing requests always win the shared row.

Phase 3 — 429 back-off softened (keyed tier makes 429s rare; Ryan approved):
  * hf_scraper.py + scraper_bridge.py: NH_RATE_LIMIT_TTL_SEC default
    60->20, NH_RATE_LIMIT_TTL_CAP_SEC default 300->120 (env-reversible).
  * ScraperBot/app/config.py: LIST_429_SLEEP_CAP_SEC default 300->120.

Phase 4 — tests: NEW tests/test_nhentai_api_key.py (pure-Python stubs, no
network) — header attached iff key set for all four helper sites +
trending_tags, keyed bucket caps, 80/20 split, softened backoff defaults.

CACHE CONTRACT: untouched. No cache-key, payload-shape, TTL, or vendored
turso_cache copy changes. No frontend/importmap changes (no JS touched).
